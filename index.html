The Tails boot menu text is too small. Here is what actually makes it bigger

On a high-resolution laptop screen, the GRUB menu on a Tails USB stick, where you pick the kernel and boot options, is microscopic. The obvious fix is to load a bigger font, and it does nothing. This page explains why, and the change that does work.

Why a bigger font doesn't help

GRUB's graphical terminal, gfxterm, keeps its embedded, roughly 16-pixel unicode font as the default, whatever you loadfont. You can build a large PF2 font, load it, and see no change at all.

What changes the size you see is the graphics resolution. At 640×480 the same 16-pixel font fills far more of the screen than at a laptop panel's native 2560×1600. So the fix is to ask GRUB for a small mode.

The fix, by hand

Add this line to Tails' GRUB configuration, immediately before terminal_output gfxterm:

set gfxmode=640x480,800x600,1024x768,auto

GRUB tries the modes in order and uses the first one your firmware actually offers, so you get the biggest text available. auto at the end is the safety net: if none of the small modes exists, GRUB falls back to its usual choice and the menu can't go blank.

Edit only the Tails system partition: the unencrypted vfat partition labelled Tails. Never touch the LUKS Persistent Storage partition. Keep a copy of each file you edit. Tails rewrites its GRUB files on every system upgrade, so the change has to be made again afterwards.

The tool: tails-bigfont

Automated: tails-bigfont makes exactly this edit. It finds the stick itself (LABEL=Tails, FSTYPE=vfat), mounts it with udisksctl without sudo where it can, inserts the gfxmode line, sets a 15-second menu timeout, keeps a one-time .bak of each config, and unmounts the same way it mounted. It is idempotent: re-running strips any earlier gfxmode or custom-font lines first, so it's safe to run again after every Tails upgrade.

./install.sh            # installs tails-bigfont, plus a tailsfont function and tailsbig alias
tails-bigfont           # plug in the stick; it finds the Tails partition
tails-bigfont -t 10     # custom GRUB timeout (default 15)
tails-bigfont -d /dev/sdb1    # pick the partition yourself if several sticks are plugged in
tails-bigfont --revert  # restore from .bak, or just remove the gfxmode line

install.sh is self-contained, with the whole tool embedded, so you can copy that one file to any Linux machine. It adds the tailsfont function and tailsbig alias to bash, zsh and fish. Free and open source, MIT licence.

FAQ

Why doesn't loading a bigger font make the Tails GRUB menu bigger?

GRUB's gfxterm keeps its embedded, roughly 16-pixel unicode font as the default no matter what you loadfont, so building a larger PF2 font and loading it makes no visible difference. Lowering the graphics resolution does: a smaller canvas makes the same font fill much more of the screen.

Does it touch my Persistent Storage?

No. Only the unencrypted Tails system partition (vfat, label Tails) is edited. The LUKS Persistent Storage partition is never touched.

Do I have to redo it after a Tails upgrade?

Yes. Tails rewrites its GRUB configuration during every system upgrade, which removes the change. Re-run the tool afterwards; it is idempotent, so running it again is always safe.

Can it leave the boot menu blank?

No. The mode list ends with auto, so if the firmware offers none of the small resolutions, GRUB falls back to its usual choice. A one-time .bak of each config is kept, and --revert restores it.
